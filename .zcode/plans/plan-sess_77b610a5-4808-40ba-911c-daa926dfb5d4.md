## 目标

让火山 Agent Plans 这类拿不到 `/api/pricing`（无按 token 定价）的平台，在使用日志里也能显示"缓存 Tokens / 缓存创建 Tokens"数量，且不产生误导性的价格/费用。

## 根因回顾

- 缓存 token 数在上游就被 `parseProxyUsage` 解析出来了，但只有 `buildProxyBillingDetails()` 返回**非 null** 时，`billingDetails` 才落库到 `proxy_logs.billing_details`（`proxyBilling.ts:78-79` → `sharedSurface.ts:250`）。
- `buildProxyBillingDetails()`（`modelPricingService.ts:840`）在「拿不到 pricingData」或「模型 quotaType===1」时直接返回 `null`（860、863 行），所以火山这类无定价平台的日志 `billing_details` 全是空。
- `estimateProxyCost()` 有 `fallbackTokenCost()` 兜底，所以成本有值，但 `buildProxyBillingDetails` 没有兜底 → 前端只能看到 cost 看不到缓存明细。

## 改动方案（用户已确认：只展示缓存 Token 数量，无价格）

### 服务端 `src/server/services/modelPricingService.ts`

1. **新增模块私有函数 `buildPricinglessBillingDetails(usage)`**：
   - 用 `normalizeUsageBreakdownInput(usage)` 归一化 usage（完整携带 `cacheReadTokens` / `cacheCreationTokens` / `billablePromptTokens`）。
   - 返回 `ProxyBillingDetails`：
     - `quotaType: 0`
     - `pricing`: modelRatio=1, completionRatio=1, cacheRatio=1, cacheCreationRatio=1, groupRatio=1
     - `breakdown`: inputPerMillion/outputPerMillion/cacheReadPerMillion/cacheCreationPerMillion 及所有 cost 全为 0
2. **`buildProxyBillingDetails()` 三个返回 `null` 的分支改为返回 `buildPricinglessBillingDetails(usage)`**：
   - `!pricingData`（原 860 行）
   - `!model || model.quotaType === 1`（原 863 行）
   - `catch` 块（原 867 行）
   - `billingPricingOverride` 分支（self-log 回填）保持不变
   - 返回类型签名 `Promise<ProxyBillingDetails | null>` 保留不变（实现不再返回 null，但保持签名窄变更，不影响现有测试 mock）

### 前端 `src/web/pages/ProxyLogs.tsx`

3. **新增 helper `isPricinglessBillingDetails(detail)`**：判断 `breakdown.inputPerMillion === 0 && breakdown.outputPerMillion === 0`。
4. **`formatBillingDetailSummary()`**（137 行）：无价格明细时返回 `null`（避免显示"模型倍率 1，输出倍率 1…"这类误导行）。
5. **`buildBillingProcessLines()`**（167 行）：无价格明细时返回 `[]`（复用现有 2059 行的 else 分支：输入/输出/总计 tokens + 预估费用，不显示 `$0 / 1M tokens`）。
   - 缓存行（2021-2057）由 `billingDetails` 非空 + `>0` 守卫驱动，自动点亮，无需改动。

### 附带收益（无需额外改动）

- `proxyLogsAnalyticsService.ts:108` 的 `readBillingCacheTokens()` 只要 `billingDetails` 非空且含 `usage.cacheReadTokens` 就会累加 → 用量分析面板的缓存统计/趋势自动点亮。

### 测试

6. 在 `src/server/services/modelPricingService.test.ts` 增加用例：
   - 无 pricingData 时 `buildProxyBillingDetails` 返回非 null，usage 携带 cacheRead/cacheCreation，breakdown 全 0。
   - `quotaType===1` 模型同样返回非 null 无价格明细。
7. 运行相关单测 + `npm run repo:drift-check`（AGENTS.md 要求）。

## 不改动

- 不改数据库 schema / 迁移（`billing_details` 列已存在）。
- 不改 `api.ts` 类型（`ProxyBillingDetails` 形状不变）。
- 不改 `estimateProxyCost` 的成本兜底逻辑（成本显示维持现状）。
- 不改有定价平台的展示（有 pricing 的模型走原 `calculateModelUsageBreakdown`，行为不变）。

## 验证

- 单测通过。
- 重启本地实例后，对火山 Agent Plans 发一次带缓存命中的请求，确认 `proxy_logs.billing_details` 落库且前端日志详情显示缓存 Tokens。
